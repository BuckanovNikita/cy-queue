# Состояние на диске

Эта страница описывает, что [очередь](../GLOSSARY.md#queue) хранит на диске: каталог очереди, каталог координации, общий каталог в `/tmp` и файлы, которые [задание (job)](../GLOSSARY.md#job) оставляет в [рабочем каталоге (project)](../GLOSSARY.md#project). Она нужна, чтобы найти журнал задания и понять, что можно удалить, а что нельзя.

Пути ниже используют `<host-id>` (идентификатор хоста), `<uid>` (UID пользователя) и `<job-id>` (полный ID задания: поле `id` в выводе `cy-queue list --json`).

## Каталог очереди

[Каталог очереди (queue root)](../GLOSSARY.md#queue-root) — `root` из `queue.toml` или `--root`:

```text
/srv/cy-queue/                          1777, если каталог создала очередь
├── queue-identity.json                 идентификатор этого каталога очереди
└── hosts/                              0777
    └── <host-id>/                      0777, раздел хоста
        └── actors/                     0777
            └── <uid>/                  0755, записи одного пользователя
                ├── worker.json         пишет worker пользователя, удаляет при остановке
                ├── batches/            0755, записи о поставленных пачках заданий
                ├── events/             0755, перестановки этого пользователя (move)
                └── jobs/               0755
                    └── <job-id>/       0755
                        ├── public.json
                        ├── snapshot.json
                        └── archive.json
```

| Файл | Режим | Кто читает | Что содержит |
| --- | --- | --- | --- |
| `public.json` | `0644` | все | Открытая сводка задания: то, что показывают `list` и `tui` (состояние, имя, запрос GPU, выделенные GPU, причина ожидания, ошибка, прогресс, ссылка ClearML). |
| `snapshot.json` | `0600` | только владелец | [Снимок задания (snapshot)](../GLOSSARY.md#snapshot): полная конфигурация CY, рабочий каталог, интерпретатор, [отпечаток окружения (package identity)](../GLOSSARY.md#package-identity). |
| `archive.json` | `0644` | все | Пометка [архива](../GLOSSARY.md#archive); появляется после первого `archive`. |

В каталоге задания есть и другие служебные файлы с режимом `0600`, которые worker пишет при запуске и отмене задания.

Каталог `<host-id>/` — [раздел хоста (host partition)](../GLOSSARY.md#host-partition). Если worker завершился аварийно, `worker.json` остаётся на месте.

Каждый пользователь пишет только в свой `actors/<uid>/`; права на каталоги описаны в [setup.md](setup.md#несколько-пользователей-на-одном-хосте). Задания не удаляются: `archive` только ставит пометку, завершённые задания остаются в каталоге очереди.

## Каталог координации

[Каталог координации (coordination root)](../GLOSSARY.md#coordination-root) — `coordination_root` из `queue.toml`. Для каждого хоста в нём есть каталог `<host-id>/` (режим `1777`) с файлами, общими для всех пользователей хоста: [резервы (reservation)](../GLOSSARY.md#reservation) GPU, [удержания (hold)](../GLOSSARY.md#hold), блокировки, через которые процессы очереди на хосте согласуют изменения каталога очереди и GPU, регистрация worker каждого пользователя и запись о текущей загрузке хоста. Читать эти файлы напрямую не нужно: состояние GPU показывает [`cy-queue gpu list`](commands/gpu.md).

## Общий каталог в `/tmp`

`/tmp/clearml-yolo-queue/<host-id>/` (режим `1777`) хранит [привязку хоста (host binding)](../GLOSSARY.md#host-binding) к каталогу координации (`coordination-root.json`), блокировки, под которыми эта привязка создаётся, и запись о текущей загрузке хоста. Привязка описана в [setup.md](setup.md#привязка-хоста-к-каталогу-координации).

## Что задание оставляет в рабочем каталоге

Рабочий каталог (project) — `CY_HOME` или текущий каталог в момент `submit`. Задание пишет в него:

| Путь | Режим | Что это |
| --- | --- | --- |
| `.cy/queue-logs/<job-id>.log` | каталог `0700`, файл `0600` | Журнал задания: stdout и stderr процесса задания. Запись дописывается в конец файла. |
| `.cy/queue-status/<job-id>.json` | файл без прав для группы и остальных | Прогресс и ссылка на задачу ClearML, которые CY пишет во время работы (путь передаётся заданию в `CY_PROGRESS_FILE`); worker переносит их в `list`. Файл должен оставаться доступным только владельцу и не превышать 64 КиБ. Иначе `list` показывает у задания предупреждение обновления, а worker владельца на очередном опросе завершается с ошибкой (`Private queue record permissions are too broad: ...` или `Child queue status is outside its project or exceeds its bound`) и не запускается, пока файл не исправлен или не удалён. |
| `outputs/queue-<hex>/` | — | Выходной каталог Hydra задания, если каталог Hydra из конфигурации CY (для sweep — `hydra.sweep`) использует `cy_run_token`, как в конфигурации CY по умолчанию. Иначе для sweep выходной каталог каждого задания — `hydra.sweep.dir`/`hydra.sweep.subdir`, а явно заданный `hydra.run.dir` обычного задания не меняется. |

Остальное содержимое рабочего каталога (временный каталог `.tmp`, результаты команды) создаёт CY, см. <https://github.com/BuckanovNikita/clearml-yolo>.

Журнал задания `job-17` найдите по его полному ID:

```bash
cy-queue list --json
tail -f /workspace/project/.cy/queue-logs/<job-id>.log
```

Журнал читает только владелец задания.

## Что переживает перезагрузку

Очередь не удаляет свои файлы при перезагрузке. Каталог очереди и каталог координации остаются как есть: задания, их состояния и резервы GPU сохраняются. Запись о загрузке хоста привязана к ID загрузки; после перезагрузки очередь пишет новую запись, а записи прошлых загрузок не удаляет.

`/tmp/clearml-yolo-queue` переживает перезагрузку, только если её переживает `/tmp`. Если каталог исчез, следующий вызов `cy-queue` создаёт его заново и привязывает хост к `coordination_root` того, кто вызвал очередь первым.

## Что можно удалять

Можно удалить:

- журнал `.cy/queue-logs/<job-id>.log` и файл `.cy/queue-status/<job-id>.json` задания в состоянии `completed`, `failed` или `cancelled`;
- выходной каталог Hydra завершённого задания, если его результаты больше не нужны.

Нельзя удалять, пока в очереди есть задания или работает worker:

- каталог очереди и что-либо внутри него. Очередь читает записи всех пользователей и отказывает, если запись повреждена или не на месте. Worker на каждом опросе читает `snapshot.json` каждого вашего задания, в том числе завершённых и архивных, и сверяет его с отпечатком в `public.json`. Если снимок любого из них удалён или изменён, worker завершается с ошибкой («Private queue snapshot is unreadable», «Private queue snapshot hash mismatch; execution refused») и не запускает ни одно ваше задание.
- каталог координации и `/tmp/clearml-yolo-queue`. В каталоге координации лежат резервы и удержания GPU: без него очередь перестаёт видеть, какие GPU заняты. В `/tmp/clearml-yolo-queue` лежит привязка хоста: без неё следующий вызов `cy-queue` может привязать хост к другому каталогу координации (см. выше).
- рабочий каталог и каталог, из которого задание поставлено в очередь, пока задание не завершилось: без них задание не запустится, а запущенное задание пишет в рабочий каталог журнал и файл прогресса («Queued project or working directory is no longer available»).
- окружение Python, из которого задание поставлено в очередь, и установленные в нём пакеты: перед запуском задание сверяет со снимком интерпретатор, версию CY и отпечаток окружения (версии всех установленных пакетов), см. [setup.md](setup.md#обновление).

Чтобы задание не показывалось в `list`, отправьте его в архив (`cy-queue archive job-17`), а не удаляйте файлы.
