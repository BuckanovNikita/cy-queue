# cy-queue gpu

`cy-queue gpu` показывает физические GPU хоста и управляет ими: ставит и снимает [удержание (hold)](../../GLOSSARY.md#hold), чтобы на GPU не запускались новые задания (job), и освобождает GPU, чей [резерв (reservation)](../../GLOSSARY.md#reservation) остался после сбоя.

Команды работают с [каталогом координации (coordination root)](../../GLOSSARY.md#coordination-root) хоста и действуют на все очереди, которые его используют.

## Примеры

```bash
cy-queue gpu list            # номера GPU, удержания и задания, держащие GPU
cy-queue gpu disable 1       # не давать новым заданиям GPU 1
cy-queue gpu enable 1        # снять своё удержание с GPU 1
cy-queue gpu free 1          # снять с GPU 1 резерв и все удержания
```

## Селекторы GPU

Команды `disable`, `enable`, `free` и `release` принимают один [селектор GPU (GPU selector)](../../GLOSSARY.md#gpu-selector):

| Селектор | Пример | Когда принимается |
| --- | --- | --- |
| физический номер GPU на хосте | `1` | только цифры, номер меньше числа GPU хоста; это номер, который печатает `gpu list`, видимость CUDA на него не влияет |
| полный UUID | `GPU-<uuid>` | `GPU-` и UUID в каноническом виде |
| [короткое имя GPU (GPU label)](../../GLOSSARY.md#gpu-label) | `gpu-<word>-<word>-<word>-<word>` | только если каталог координации уже знает этот GPU (на нём есть резерв, удержание или он уже освобождался) и имя однозначно |

Отказы:

| Ввод | Сообщение |
| --- | --- |
| номер не меньше числа GPU, например `5` на хосте с двумя GPU | `GPU physical index is outside the NVML inventory` |
| короткое имя, которого каталог координации не знает | `GPU short selector is unknown or ambiguous` |
| всё остальное: `-1`, `+1`, `1.0`, `0,1`, ` 0 `, `MIG-...`, неполный UUID, пустая строка | `GPU selector must be a nonnegative physical index or known short label` |

При отказе ничего не записывается. Сообщения печатаются в stderr с префиксом `cy-queue: `.

## gpu list

Показывает каждый физический GPU хоста и каждый GPU, который знает каталог координации.

### Синтаксис и аргументы

```text
cy-queue gpu list [-h] [--json]
```

| Аргумент | По умолчанию | Описание |
| --- | --- | --- |
| `--json` | выключен | Напечатать список в JSON ([JSON](../formats/json.md)). |

### Результат

Одна строка на GPU, поля разделены табуляцией:

```text
0	holds=-	job=-
1	holds=uid=1000	job=owned by user 1000
```

| Поле | Значение |
| --- | --- |
| первое | физический номер GPU; для GPU, которого сейчас нет в списке хоста, — его короткое имя `gpu-<word>-<word>-<word>-<word>` |
| `holds=` | удержания на GPU, `uid=<UID>` через `; `, или `-` |
| `job=` | `owned by user <UID>`, если GPU в резерве задания этого пользователя, иначе `-` |

#### Коды завершения

| Код | Значение |
| --- | --- |
| `0` | список напечатан |
| `1` | ошибка чтения GPU или каталога координации |

## gpu disable

Ставит на GPU ваше удержание.

### Синтаксис и аргументы

```text
cy-queue gpu disable [-h] [--json] selector
```

| Аргумент | По умолчанию | Описание |
| --- | --- | --- |
| `selector` | обязателен | Селектор GPU. |
| `--json` | выключен | Напечатать запись удержания в JSON. |

### Как это работает

1. Команда разбирает селектор.
2. Она записывает удержание от вашего UID. У каждого пользователя на GPU своё удержание; повторный `disable` его перезаписывает.
3. Пока на GPU есть удержание любого пользователя, ни одна очередь, использующая этот каталог координации, не запускает на нём новое задание.
4. Задание, которое уже работает на GPU, удержание не трогает: оно продолжает работать.

### Результат

```text
GPU 1: own hold added
```

Если GPU указан не номером, а UUID или коротким именем, в сообщении стоит короткое имя GPU.

#### Коды завершения

| Код | Значение |
| --- | --- |
| `0` | удержание поставлено |
| `1` | неверный селектор или ошибка каталога координации |
| `2` | нет селектора |

## gpu enable

Снимает с GPU ваше удержание.

### Синтаксис и аргументы

```text
cy-queue gpu enable [-h] [--json] selector
```

| Аргумент | По умолчанию | Описание |
| --- | --- | --- |
| `selector` | обязателен | Селектор GPU. |
| `--json` | выключен | Напечатать `{"status": "hold removed"}`. |

### Как это работает

1. Команда разбирает селектор.
2. Она удаляет только удержание от вашего UID. Удержания других пользователей остаются, и GPU не получает новых заданий, пока они есть. Снять все удержания сразу можно через `gpu free`.
3. Если вашего удержания нет, команда всё равно завершается успешно.

### Результат

```text
Own GPU hold removed
```

#### Коды завершения

| Код | Значение |
| --- | --- |
| `0` | вашего удержания на GPU больше нет |
| `1` | неверный селектор или ошибка каталога координации |
| `2` | нет селектора |

## gpu free и gpu release

`gpu free` и `gpu release` — одна и та же команда под двумя именами. Она [освобождает GPU](../../GLOSSARY.md#free-gpu): снимает с него резерв задания и удержания всех пользователей, чтобы очередь снова могла выдать его новому заданию.

> GPU освобождается сразу и без проверок. Если процесс задания ещё работает на этом GPU, следующее задание может запуститься рядом с ним.

### Синтаксис и аргументы

```text
cy-queue gpu free [-h] [--json] selector
cy-queue gpu release [-h] [--json] selector
```

| Аргумент | По умолчанию | Описание |
| --- | --- | --- |
| `selector` | обязателен | Селектор GPU. |
| `--json` | выключен | Напечатать запись об освобождении в JSON. |

### Как это работает

1. Команда разбирает селектор. Короткое имя GPU, которого уже нет в списке хоста, тоже принимается, если его знает каталог координации.
2. Она записывает в каталог координации событие освобождения для этого GPU. После него прежний резерв и все прежние удержания на GPU, в том числе чужие, больше не учитываются.
3. Команда не смотрит на процессы, занятую память, задания и их состояние. Она не останавливает ни один процесс и не меняет состояние задания: задание, чей резерв снят, остаётся в прежнем состоянии, а его выделенные GPU (allocation) больше не включают этот GPU.
4. Резерв задания на других GPU не меняется.

Освобождение не доказывает, что GPU свободен. Перед `gpu free` убедитесь сами (например, через `nvidia-smi`), что на GPU не осталось процессов задания. Для задания в `recovery_required` сначала попробуйте [`recover`](jobs.md#recover): он сам останавливает оставшиеся процессы и снимает резерв.

### Результат

```text
GPU 1: reservations and holds cleared
```

Если GPU указан не номером, а UUID или коротким именем, в сообщении стоит короткое имя GPU. С `--json` печатается запись об освобождении ([JSON](../formats/json.md)).

#### Коды завершения

| Код | Значение |
| --- | --- |
| `0` | GPU освобождён |
| `1` | неверный селектор или ошибка каталога координации |
| `2` | нет селектора |

## Частые ошибки

| Сообщение | Причина и что делать |
| --- | --- |
| `GPU physical index is outside the NVML inventory` | На хосте нет GPU с таким номером. Посмотрите номера в `cy-queue gpu list`. |
| `GPU short selector is unknown or ambiguous` | Каталог координации не знает GPU с таким коротким именем, или имени соответствуют несколько GPU. Укажите физический номер или `GPU-<uuid>`. |
| `GPU selector must be a nonnegative physical index or known short label` | Селектор не номер, не `GPU-<uuid>` и не короткое имя. |
